# PowerBI_Dashboard-Before_vs_After_Optimization
## Project Overview
This project demonstrates a Before vs After Power BI dashboard audit, focused on identifying and correcting common reporting and UX issues. Starting from a realistic but poorly structured dashboard, the project showcases how clearer KPI prioritization, reduced visual clutter, and improved layout significantly enhance usability and decision‑making. The final result is a clean, executive‑ready dashboard designed around business relevance rather than visual overload.

## Business Issue
Many organizations have dashboards that technically work but fail to support decision‑making due to:
- Too many KPIs without prioritization
- Redundant or overlapping visuals
- Poor visual hierarchy
- Overuse of slicers and tables
- Lack of a clear analytical narrative
This project addresses these issues through a structured dashboard audit and redesign.

---
## Power BI Dashboard
### BEFORE Dashboard - Key Issues Identified
The original dashboard intentionally reflects common real‑world problems:
  - KPI overload with no clear focus
  - Multiple charts communicating the same information
  - Pie charts and tables that add little analytical value
  - Excessive slicers causing user confusion
  - No clear “primary” insight for business users    
Although technically correct, the dashboard is inefficient and difficult to interpret.

---

###  AFTER Dashboard - Improvements Implemented
The redesigned dashboard focuses on clarity and usability:
- Reduced KPI set (Total Revenue, Revenue per Order, Estimated Profit)
- Clear primary visual (Revenue Trend Over Time)
- Supporting visuals limited to business‑critical breakdowns
- Minimal slicers to guide analysis without overwhelming users
- Clean layout suitable for executive and client reporting

---

## Data Model & Assumptions
- Star‑schema model with Customers, Products, Orders, and Order Items
- Revenue calculated from transactional data
- Estimated Profit calculated using an assumed 30% gross margin, due to missing cost data
- The assumption is explicitly documented and used consistently
